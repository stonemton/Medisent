# Medisent

Telegram-бот подбора поставщиков медицинских изделий с проверкой регистрации
в реестрах Росздравнадзора и автоматической сборкой коммерческого предложения
в PDF.

### Быстрый старт локально

```bash
cp .env.example .env          # заполнить TELEGRAM_BOT_TOKEN и TELEGRAM_OWNER_ID
make up                       # поднять бота, Postgres и Mathesar
make migrate                  # создать таблицы
make logs                     # смотреть, что происходит
```

### Проверки

```bash
make check                    # ruff + mypy --strict + pytest
```

Интеграционные тесты требуют **отдельной** базы:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost/medisent_test pytest
```

Без этой переменной они пропускаются, остальные проходят.

### Структура

```
bot/
  main.py            точка входа, роутеры, фоновые задачи
  config.py          всё из окружения, ключей в коде нет
  texts.py           все тексты для владельца, в хендлерах строк нет
  pipeline.py        оркестрация: поиск → скрейп → реестр → отчёт
  scheduler.py       опрос почты, бюджет, heartbeat
  middleware.py      доступ только владельцу, антифлуд
  handlers/          intake (приём), selection (выбор, письмо, КП), admin
  services/
    http.py          единственный выход наружу: таймаут, ретрай, учёт расходов
    registry.py      реестры Росздравнадзора, без LLM
    registry_endpoints.py   адреса и разбор ответов — правится при смене API
    gemini.py        мультимодальный вход и JSON-вывод
    perplexity.py    поиск поставщиков
    firecrawl.py     чтение сайтов
    report.py        отчёт: LLM отдаёт JSON, рендерит код
    criteria.py      накопление критериев выбора
    mail.py          Gmail: отправка и матчинг ответов
    kp.py            извлечение цен и сборка PDF
    batch_intake.py  распознавание многопозиционных заявок
    procurement_batch.py  объединение поиска по общим поставщикам
    guard.py         защита от инъекций в чужом тексте
  db/
    models.py        схема
    repo.py          весь SQL проекта
    migrations/      Alembic
prompts/             инструкции для LLM, читаются с диска
tests/               тесты, включая батч-заявки и коэффициент продажи
scripts/             бэкап базы, получение токена Gmail
```

## Состояние

Этапы 0–8 из ТЗ реализованы, замечания аудита и ревью закрыты. Дополнительно
реализован многопозиционный закупочный сценарий: фото/файл/список разбирается
на отдельные позиции, каждая проверяется по РУ, затем бот ищет поставщиков по
каждой позиции и формирует общий shortlist только из тех, кто подтверждён по
всему списку. Если общего поставщика нет, бот предлагает разбиение закупки.

В расчёте КП закупочная цена сохраняется отдельно, а продажная цена формируется
по базовому коэффициенту 1.8 и именно она попадает в клиентское КП после
подтверждения владельцем.

Не проверено на живых данных и требует первого прогона у владельца:

- **формат ответов реестров Росздравнадзора** — из среды сборки к ним нет
  сетевого доступа; при расхождении правится один файл
  `bot/services/registry_endpoints.py`. Порядок действий —
  [`docs/TODO-LAUNCH.md`, часть C](docs/TODO-LAUNCH.md#часть-c-реестры-росздравнадzora-требуется-разработчик);
- **сборка Docker-образа** — первую сборку делает Railway.
